## 解读

- 没有 `--gpus all` 时，容器完全看不到 GPU 设备，`nvidia-smi` 这个可执行文件本身也不在容器文件系统里
  （`nvidia/cuda` base 镜像不打包 `nvidia-smi`，它是由 NVIDIA Container Runtime 在 `--gpus` 生效时
  从宿主机挂载进容器的）。报错是 "not found in $PATH"，不是权限或驱动问题，说明 GPU 直通完全没有发生。
- 加上 `--gpus all` 后，容器内的 `nvidia-smi` 读到的驱动版本（610.43.02 / KMD 610.47）和 GPU 型号
  （RTX 4070，12282MiB）与宿主机 [environment-baseline.md](../environment-baseline.md) 记录的完全一致
  —— 说明容器复用的是宿主机（Windows 主机）的 GPU 驱动，而不是在容器里单独装了一份驱动。
- host driver 与 container CUDA 的关系：驱动（含 kernel-mode driver、GPU 硬件访问）永远只装在宿主机上，
  且必须由宿主机提供；容器内只需要与之兼容的 CUDA **用户态**库/工具链（不同容器可以带不同版本的 CUDA
  Toolkit，只要不高于宿主机驱动支持的最高 CUDA 版本）。这也是为什么 [environment-baseline.md](../environment-baseline.md)
  里 Windows nvcc 是 13.3 而 WSL nvcc 是 12.0 却都能正常工作——nvcc 版本只是编译器版本，真正决定兼容性
  的是驱动版本和运行时库版本。
- 当前 GPU 已有 9091MiB/12282MiB 被占用（推测是 Windows 侧应用/WDDM 常驻占用），后续做 CUDA 基准测试
  （Day 4）时需要把这部分基线占用记进报告，避免把"可用显存变少"误判为基准程序本身的问题。
